# 로컬 스케줄러

내 PC에서만 도는 작업 스케줄러. **Claude Code 프롬프트**와 **셸 명령**을 정해진 시각에 자동 실행하고,
결과를 브라우저 대시보드에서 확인한다.

- **Windows · macOS · Linux 공용** — 플랫폼 차이는 프로그램이 흡수한다
- **외부 의존성 0** — Node.js 내장 모듈만 사용한다 (`npm install` 이 필요 없다)
- **로컬 전용** — `127.0.0.1` 에만 바인딩한다. 외부에서 접속할 수 없다
- **파일 기반** — 모든 데이터가 `data/` 폴더에 있어 폴더째 복사하면 다른 PC로 옮겨진다

---

## 시작하기

필요한 것은 **Node.js 18.17 이상**뿐이다. Claude Code 작업을 쓰려면 `claude` CLI 가 PATH 에 있어야 한다.

```bash
cd local-scheduler
npm start
```

브라우저에서 **http://127.0.0.1:4321** 을 연다. 이 방식은 터미널을 닫으면 함께 꺼진다.

### 백그라운드로 띄우기

```bash
npm run bg        # 창 없이 백그라운드 시작 (터미널을 닫아도 계속 돈다)
npm run stop      # 종료
npm run restart   # 재시작 — 폴더를 옮긴 뒤에 쓴다
```

부팅할 때부터 자동으로 돌게 하려면 아래 **부팅 시 자동 시작**을 쓴다.
등록과 동시에 지금 바로 백그라운드 실행까지 해준다.

### 부팅 시 자동 시작

```bash
npm run install-service     # 등록
npm run service-status      # 상태 확인
npm run uninstall-service   # 해제
```

| 플랫폼 | 등록 방식 | 관리자 권한 |
|---|---|---|
| Windows | 시작프로그램 폴더에 VBS 런처 (콘솔 창이 뜨지 않음) | 불필요 |
| macOS | `~/Library/LaunchAgents` 의 launchd 에이전트 (`KeepAlive` 로 죽으면 재시작) | 불필요 |
| Linux | `systemd --user` 서비스 | 불필요 |

> macOS 에서 로그아웃 상태에서도 돌리려면 `sudo loginctl enable-linger $USER` 가 필요하다(Linux 동일).

## 작업 만들기

대시보드에서 **＋ 새 작업**을 누른다.

### 실행 종류

**Claude Code** — 프롬프트를 비대화형(`claude -p`)으로 실행한다.
프롬프트는 명령행 인자가 아니라 **표준입력으로 전달**하므로 따옴표·줄바꿈·한글이 섞여도 깨지지 않는다.

```
매일 아침 어제 활동을 수집해서 요약해줘. /kb-daily 를 실행하면 된다.
```

**셸 명령** — Windows 는 `cmd.exe`, macOS·Linux 는 `/bin/sh` 로 실행한다.

```
node C:\ai\scripts\backup.js
```

### 스케줄

프리셋에서 고르거나 cron 표현식을 직접 쓴다. 입력하는 즉시 **한국어 해석과 다음 5회 실행 시각**을 미리 보여준다.

```
분 시 일 월 요일
 0  9  *  *  1-5     평일 오전 9시
*/15 *  *  *  *      15분마다
 30 8  1  *  *       매월 1일 오전 8시 30분
 0  9,18 * * *       매일 오전 9시와 오후 6시
```

`*` `,` `-` `*/n` `5/15` 와 `@daily` `@hourly` 계열 매크로, 요일·월 이름(`MON`, `JAN`)을 지원한다.
일·요일을 **둘 다** 지정하면 표준 cron 과 동일하게 OR 로 동작한다.
모든 시각은 **PC 의 로컬 타임존** 기준이다.

### 모델 (Claude 작업)

목록에서 고르거나 직접 입력한다. 비워두면 Claude Code 기본 모델을 쓴다.

| 입력 | 뜻 |
|---|---|
| `opus` | 최신 Opus — 대부분의 작업에 권장 |
| `sonnet` | 더 빠르고 저렴 |
| `haiku` | 가장 빠르고 저렴 — 단순 수집·요약용 |
| `fable` | 가장 강력 |
| `claude-opus-5` | 버전 고정 (별칭과 달리 자동으로 올라가지 않음) |

별칭(`opus` 등)은 항상 그 계열의 **최신** 모델을 가리킨다. 매일 도는 작업이라면 별칭이 편하고,
결과를 재현해야 하는 작업이라면 전체 ID로 고정하는 편이 낫다.

### 권한 모드 (Claude 작업)

무인 실행이라 도구 사용 승인을 사람이 눌러줄 수 없다. 프롬프트가 하는 일에 맞춰 고른다.

| 모드 | 동작 |
|---|---|
| `default` | 승인이 필요한 도구는 거부된다 |
| `acceptEdits` *(기본)* | 파일 수정을 자동 승인한다 |
| `plan` | 계획만 세우고 실행하지 않는다 |
| `bypassPermissions` | 모든 확인을 생략한다 — **신뢰할 수 있는 프롬프트에만** |

더 좁게 열고 싶으면 고급 옵션의 **허용 도구**에 `"Bash(git:*)" "Read"` 처럼 지정한다.

### 작업 디렉토리

**절대경로**로 쓴다. 비우면 홈 디렉토리에서 실행한다.

```
C:\ai\datahub          Windows 절대경로
/Users/이름/ai/datahub   macOS 절대경로
~/ai/datahub           두 PC 공용 — 각자의 홈 기준으로 풀린다
```

두 PC에서 같은 작업을 쓰는데 경로가 다르다면 두 가지 방법이 있다.

1. `~` 로 시작하는 공용 경로를 쓴다 (홈 아래에 같은 구조로 두었을 때)
2. **macOS에서의 경로**를 따로 지정한다 — Windows는 위 경로를, Mac은 이 경로를 쓴다

지정한 경로가 그 PC에 없으면 저장은 되지만 목록에 **경로 없음** 표시가 붙고,
실행할 때는 홈 디렉토리로 폴백하면서 로그 첫머리에 경고를 남긴다. 조용히 엉뚱한 곳에서 도는 일은 없다.

### 그 밖의 옵션

- **타임아웃** — 초과하면 자식 프로세스까지 통째로 강제 종료한다 (기본 30분)
- **놓친 일정 보정** — PC 가 꺼져 있어 건너뛴 일정을 재시작 후 1회 실행한다. 여러 번 밀렸어도 1회만 돈다

## 동작 방식

- 매 분 경계에 깨어나 각 작업의 다음 실행 시각을 확인한다
- 같은 작업이 아직 돌고 있으면 **건너뛴다** (중복 실행 없음)
- 다음 실행 시각은 `data/state.json` 에 저장하므로 PC 를 껐다 켜도 놓친 일정을 판단할 수 있다
- 실행 로그는 작업당 최근 **50건**을 보관하고, 오래된 것부터 자동으로 지운다
- 한국어 Windows 의 `cmd.exe` 는 CP949 로 출력하므로 출력 인코딩을 자동 판정해 한글이 깨지지 않게 기록한다

### 데이터 위치

```
data/
  jobs.json          작업 정의      ← 두 PC 간 공유 대상
  state.json         다음 실행 시각  (PC 별)
  runtime.json       마지막 실행 결과 (PC 별)
  runs/<작업id>/
    index.json       실행 이력 메타  (PC 별)
    <실행id>.log     실행 로그      (PC 별)
```

실행 결과를 `jobs.json` 이 아니라 `runtime.json` 에 두는 이유는, 작업 정의 파일이 실행할 때마다
바뀌면 두 PC 동기화에서 매번 충돌하기 때문이다.

`SCHEDULER_DATA_DIR` 환경변수로 위치를 바꿀 수 있다.

## 두 PC에서 작업 설정 공유하기

작업 정의(`data/jobs.json`)와 코드만 git으로 공유하고, 실행 이력·로그·다음 실행 시각은 각 PC에 둔다.

### 최초 설정 (한 번만)

```bash
cd local-scheduler
git init
git add -A && git commit -m "로컬 스케줄러 최초 커밋"
git remote add origin <두 PC가 함께 쓸 저장소 URL>
git push -u origin main
```

> **개인(private) 저장소를 쓴다.** 프롬프트에 업무 내용이 들어간다.

다른 PC에서는 clone 한 뒤 `npm start` 만 하면 된다.

### 이후 사용

```bash
npm run sync          # 받고 → 올린다
npm run sync-pull     # 받기만
npm run sync-status   # 무엇이 다른지 확인
```

동기화 후 스케줄러가 **1분 안에** 새 작업 목록을 자동으로 반영한다. 재시작할 필요가 없다.

### 알아둘 점

- **양쪽 PC가 다 켜져 있으면 같은 작업이 양쪽에서 각각 실행된다.** 스케줄러끼리 서로를 모른다.
  한 번만 돌아야 하는 작업이라면 한쪽에서 작업을 비활성화해 둔다.
- 같은 작업을 두 PC에서 동시에 고치면 `jobs.json` 에서 충돌이 난다. `npm run sync` 가 어디를 고쳐야 하는지 알려준다.
- 경로가 다른 작업은 위 **작업 디렉토리** 절의 `~` 또는 macOS 경로 지정으로 해결한다.

## 설정

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `SCHEDULER_PORT` | `4321` | 대시보드 포트 |
| `SCHEDULER_DATA_DIR` | `./data` | 데이터 폴더 |
| `CLAUDE_BIN` | `claude` | Claude Code 실행 파일 경로 |

## 보안

이 대시보드는 **임의의 명령을 실행할 수 있다**. 그래서:

- 서버는 `127.0.0.1` 에만 바인딩한다. `0.0.0.0` 으로 바꾸지 말 것
- `Host` 헤더가 localhost 가 아닌 요청은 거부한다 (DNS 리바인딩 방어)
- 인증이 없다. 이 PC 를 쓰는 사람은 누구나 대시보드에 접근할 수 있다

원격에서 쓰고 싶다면 포트를 여는 대신 SSH 터널을 쓴다.

```bash
ssh -L 4321:127.0.0.1:4321 사용자@내PC
```

## 문제 해결

**포트가 이미 사용 중입니다**
이미 실행 중이거나(자동 시작 등록 후 수동 실행한 경우) 다른 프로그램이 4321 을 쓰고 있다.

```bash
# Windows
powershell "(Get-NetTCPConnection -LocalPort 4321 -State Listen).OwningProcess"
# macOS / Linux
lsof -i :4321
```

**Claude 작업이 곧바로 실패한다**
`claude` 가 PATH 에 없거나 로그인이 안 된 상태다. 터미널에서 `claude -p "안녕"` 이 되는지 먼저 확인한다.
자동 시작으로 띄운 경우 PATH 가 다를 수 있으니 `CLAUDE_BIN` 에 전체 경로를 지정한다.

**예정 시각보다 1~2초 늦게 실행된다**
정상이다. 분 경계 직후에 깨어나도록 설계했다.

**PC 가 절전 상태였다**
절전 중에는 실행되지 않는다. 깨어난 뒤 실행되게 하려면 **놓친 일정 보정**을 켠다.
